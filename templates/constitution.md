# Project constitution

Replace this guidance with the project's confirmed durable rules. Keep only
relevant rules grounded in approved requirements or existing conventions; discuss
unconfirmed suggestions before making them binding. This starter is not policy.

- Scope: the approved outcome and explicit exclusions; how scope changes are agreed.
- Architecture: existing boundaries and the project's criteria for extra complexity.
- Layout: where source, generated artifacts, documentation and private settings belong.
- Verification: the project's checks and evidence required before declaring work complete.
- Dependencies and security: confirmed dependency choices, secret handling and relevant safeguards.
- Collaboration: applicable review, handoff and preservation practices.

Use concise concrete rules with project-relative references where useful. Omit
machine paths, secrets and developer identities. Do not import ThisDamnThing's source
repository development policies or make a no-tests rule by default.
